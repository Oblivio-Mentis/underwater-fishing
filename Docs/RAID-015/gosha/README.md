# Дрессировка Гоши

На сборке `b93d759` независимый Windows-клиент нажал **H**, и общий Гоша принёс ему одну рыбу-иглу с исходным `CargoId 5014640262100495341`. На приёме все карманы были заняты. Гоша дождался свободного кармана, после чего тот же ID прошёл через клеть и резервуар. После переработки общий кошелёк получил **4 биомассы**. Хосту, который отправлял клеть, отдельный улов не достался. [Игровой кадр 1280×720](gosha-brings-catch.webp) · [37 проверок поручения](orders-windows.json)

| Навык | Игровая проверка |
| --- | --- |
| G1 · Знакомый сигнал | **G** подзывает приручённого Гошу. Игрок с одним G1 мог вызвать его, но получил отказ на команду добычи. |
| G2 · Принеси рыбку | **H** запускает одно поручение. Сервер зарезервировал свободную малую рыбу и отказал второй, одновременно пришедшей команде. Гоша проплыл и пробежал 88,63 м. Обе гермодвери он пересёк по два раза, каждый раз при полностью открытом проходе. |
| G3 · Осторожный пловец | В действующей сцене сравнили обычный и осторожный шаг по одной траектории к донному капкану. Осторожный пловец выбрал обход с меньшей опасностью. На морском маршруте он также учитывает активных хищников. |
| G4 · Лучший рыбак | После сигнала хоста оба игрока видели одну паузу. Игрок с G4 смог отправить следующее поручение через 31,5 с при базовых 42 с. Радиус поиска вырос с 28 до 33,6 м. |

Два отдельных Windows-процесса прошли также 68 проверок прежнего приручения, поглаживания и мяча. После полного перезапуска хоста и клиента ещё четыре проверки подтвердили загруженную команду и одного приручённого Гошу. [Регресс и контрольные суммы](regression.json)

Проверка использовала два тестовых LAN-профиля и отдельное сохранение. Для сценария поручений фикстура подготовила приручённого питомца, различающиеся наборы навыков и занятые карманы. Рыбу выбрала игровая логика из живого косяка. Игроков для проверки клети и терминала ставили к оборудованию, Гоша проходил весь путь самостоятельно. Это подключение по локальной сети.

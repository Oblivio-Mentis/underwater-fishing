# Проверка Steam на двух устройствах

Нужны два Windows-устройства, два разных аккаунта с запущенным Steam и одна и та же распакованная development-сборка. App ID `480` используется с разрешения пользователя для этого прототипа. Пароли, Steam Guard, токены и доступ к аккаунту никому передавать не нужно.

Сверьте версию сборки и SHA-256 `UnderwaterFishing_Data\Managed\Assembly-CSharp.dll`. Поиск показывает только лобби с совпадающими `game=underwater-fishing-raid`, `protocol=raid-core-1` и `build=Application.version`. Одинаковая надпись версии сама по себе не заменяет одинаковый архив.

## Запуск из папки portable-сборки

Откройте PowerShell в папке с `UnderwaterFishing.exe`. Обычный запуск на каждом устройстве:

```powershell
.\UnderwaterFishing.exe --steam-app-id 480
```

Хост нажимает **«Создать Steam-лобби»**. Для автоматического создания в development-сборке можно запустить:

```powershell
.\UnderwaterFishing.exe --steam-app-id 480 --raid-steam-host -logFile .\steam-host.log
```

Хост передаёт другу показанный в меню **Steam Lobby ID** — это номер лобби, не пароль. Второй игрок нажимает **«Найти Steam-лобби»** и выбирает нужную строку либо вводит номер в поле **Steam Lobby ID** и нажимает **«Войти по Steam Lobby ID»**. Также можно запустить клиент сразу с номером; замените пример реальным ID:

```powershell
.\UnderwaterFishing.exe --steam-app-id 480 +connect_lobby 109775240000000000 -logFile .\steam-client.log
```

`+connect_lobby` имеет приоритет над автоматическим созданием. Для этой проверки не добавляйте LAN-флаги `--raid-host` / `--raid-join` или ботов. При ошибке Steam автоматического перехода на LAN нет.

## Приглашение

Сначала запустите **обе копии прототипа**. Получатель нажимает **«Найти Steam-лобби»**, хост — **«Пригласить друзей через Steam»**. Примите приглашение в Steam. Дополнительно проверьте переход по приглашению из уже подключённой сессии: прежняя сессия должна завершиться, затем открыться новое лобби. Если создание, поиск или вход ещё выполняется, дождитесь результата и примите приглашение повторно.

Если оверлей отключён или ещё не готов, игра покажет номер лобби для ручного входа. Valve отмечает, что оверлей может подключаться несколько секунд; его доступность зависит и от способа запуска игры. [IsOverlayEnabled](https://partner.steamgames.com/doc/api/ISteamUtils#IsOverlayEnabled), [Steam Overlay](https://partner.steamgames.com/doc/features/overlay).

Valve документирует два пути приглашения: работающая игра получает `GameLobbyJoinRequested_t`, закрытая запускается с `+connect_lobby`. App ID `480` принадлежит примеру **Spacewar**. Поэтому для portable-прототипа холодный запуск по приглашению нельзя считать запуском нашего EXE: Steam может открыть зарегистрированный Spacewar. Это вывод из привязки App ID, а не проверенный здесь результат на втором устройстве. Проверяем приглашение при уже запущенном прототипе; холодный запуск относится к отдельной проверке собственного App ID и настроенного запуска в Steam. [Steam Matchmaking & Lobbies](https://partner.steamgames.com/doc/features/multiplayer/matchmaking), [Spacewar](https://partner.steamgames.com/doc/sdk/api/example).

## Автоматическая проверка реального удалённого подключения

Хост остаётся в своём лобби на другом устройстве. Закройте лишнюю копию прототипа на клиентском устройстве. Если в архив включена папка `tools`, выполните из папки portable-сборки:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\Verify-SteamRemote.ps1 -LobbyId 109775240000000000 -BuildPath .\UnderwaterFishing.exe
```

Скрипт запускает **один видимый клиент**, ждёт до 120 секунд (можно задать `-TimeoutSeconds 240`) и завершает только запущенный им процесс. Он требует запись `RAID_STEAM_CONNECTED` от выбранного FishySteamworks с действительными Steam ID, разные ID клиента и хоста и не менее двух сетевых водолазов в течение 10 секунд. `PASS` подтверждает только это подключение, не весь игровой сценарий.

В `SteamRemoteResults\<дата-время>\` сохраняются `client.log`, `result.json` и хеши сборки. В логе есть числовые Steam ID; паролей и токенов скрипт не запрашивает. При отсутствии второго аккаунта результат остаётся непроверенным: локальный Steam smoke-тест и пять LAN-процессов не доказывают совместную игру двух или пяти Steam-аккаунтов.

## Ручная приёмка после подключения

- [ ] Создание и поиск: второй аккаунт видит совместимое лобби; вход по ID тоже работает.
- [ ] Приглашение при запущенной игре: вход из меню и переход из другой подключённой сессии; без зависшего старого хоста/клиента.
- [ ] Оба видят двух водолазов; движение, поворот и выход через шлюз видны друг другу.
- [ ] Запустить экспедицию вдвоём, поймать рыбу с помощью напарника, перенести и поднять груз, вернуться; общий отсек и материалы совпадают.
- [ ] Переработать предмет, купить улучшение, изготовить и использовать сонар; после следующего выхода виден реальный эффект улучшения.
- [ ] После трёх дней зарезервировать/передать подношение; оба видят результат и одинаковую новую квоту.
- [ ] Хост закрывает игру: клиент получает завершение сессии и возвращается в меню. Миграции хоста нет; затем можно войти в новое лобби.

Для отчёта приложите версию/хеши, логи обеих сторон и отметьте каждый пункт отдельно. Проверка пяти участников требует пяти разных Steam-аккаунтов. Внешняя проверка двух аккаунтов и приглашений на момент подготовки этого документа **не выполнена**.

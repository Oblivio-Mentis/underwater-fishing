## Ошибки, устранённые практическим прогоном

1. Kimi 2.8.0 отклонял продолжение: `unload_tools ... Agent ... not declared`.
   Рабочий runner переключён на стабильную 2.8.1; та же сессия восстановлена.
   Источник версии: [официальный релиз 2.8.1](https://github.com/MoonshotAI/kimi-code/releases/tag/%40moonshot-ai%2Fkimi-code%402.8.1),
   где отмечено исправление возобновления при изменении инструментов.
2. В окружении MCP-процесса Kimi обнаружены локальный HTTP-прокси и IPv6 `NO_PROXY`,
   вызывавший у HTTPX `Invalid port: ':1]'`. Для фиксированных MCP-адресов используется
   прямое HTTP-соединение; Git и GitHub GET также используют проверенный прямой маршрут.
   Пользовательские глобальные настройки прокси не менялись.
3. Git из дочернего MCP-процесса зависал при унаследованном stdin. Для команд теперь
   задан `DEVNULL`; входной канал протокола не наследуется. Проверка повторена Kimi.
   Таймаут останавливает всё дерево команды, включая Git for Windows wrapper и потомков.
4. Неавторизованный GitHub GET упирался в rate limit. Ограниченный GET использует
   существующие данные Windows Git Credential Manager только в памяти; Kimi получает
   разрешённые результаты API, без токена и права произвольного URL/метода.

## Параллельность, приёмка и границы

Codex и Kimi реально работали одновременно: Kimi выполнял изолированное задание,
Codex проверял и исправлял инфраструктуру. Для последующей разработки Lead назначает
непересекающиеся области, отправляет полноценные ТЗ через MCP, сохраняет сессию,
читает изменения и возвращает замечания. `review` проверяет область/хэши;
`decide accept|reject --reason ...` фиксирует решение Lead. Автоматического merge нет.

Живым Unity Editor управляет только Codex. Kimi читает его через шлюз и редактирует
назначенные исходники в своём worktree. Импорт, компиляция, сцены, префабы, сборки и
Unity-тесты выполняются в последовательной интеграционной фазе. Прямая мутация живого
Editor двумя агентами не разрешена. Отдельный Unity Editor для Kimi не настраивался.

Профиль и шлюз ограничивают рабочие инструменты; это не отдельная учётная запись ОС
или VM. Добавленная Lead произвольная команда в `checks` является доверенным расширением:
сначала требуется проверить её код и область действий. Полной копии всех инструментов
Codex у Kimi нет: полномочия разделены по ролям.

Обязательных действий пользователя для этого рабочего процесса **не требуется**.
Для будущей работы с живым Blender отдельно понадобится привести в рабочее состояние
его аддон и сервер; этот канал сейчас не подтверждён и не блокирует делегирование
кода/документов с приёмкой Unity со стороны Codex. Генерация бинарных ассетов Kimi,
отдельный worker Editor, самостоятельные Unity-запуски Kimi и GitHub-записи от его
имени в данный набор полномочий не входят.
